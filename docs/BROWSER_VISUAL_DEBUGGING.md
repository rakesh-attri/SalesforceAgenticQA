## Permission and capture boundary

An optional `visualDebug` object is part of the canonical browser-plan hash. Existing signed policies omit it and cannot acquire screenshots from an environment variable or a tool argument. Review preparation remains inactive; changing screenshot limits/masks requires an exact new approval. Captures share the existing org/user/persona/build/app/state proof, record scope, session clock and request/action boundaries. They reserve no additional browser session and grant no network or mutation permission.

```json
{
  "permission": "approved-masked-local-only",
  "maxCaptures": 8,
  "maxTotalBytes": 8388608,
  "maxCaptureMs": 1500,
  "milestonesMs": [0, 1000, 3000],
  "maskLocators": [],
  "residualSensitiveContentAcknowledged": true
}
```

The schema caps captures at twelve, image bytes at 16 MiB and each capture at three seconds. Up to four milestones use the original session clock. Two slots are reserved from milestone use for terminal/operator evidence. Missing/failed captures consume their attempt and retain a finite reason, never trigger unlimited retry or extend an expired budget. Reviewed-view polling leaves capture time within the original observation allowance; it does not relax the expected name/content/stability assertions. No animation fast-forward, scrolling/full-page expansion, arbitrary screenshot options or external upload occurs.

Only an exact approved record document with verified native identity/build can be captured. Authentication/unapproved URLs, query-bearing documents, unverified record documents and detected password/OTP/login forms are refused. Known input/editable values, frames, media, common Salesforce field-value elements, private API name bindings, reviewed masks, credential/email/identifier patterns, configured secrets and known session-cookie values are masked. Visible alert bodies are masked after local finite error classification. Raw DOM, error text, cookie values and URLs are absent from the manifest.

**Complete masking cannot be guaranteed.** Custom closed-shadow components, unusual widgets and unknown text can contain sensitive content. Images remain local and carry that warning. Review them manually before any sharing; no automated AI indexing/upload path consumes these files. PNGs and manifests are inside ignored `artifacts/`; local filesystem permissions inherit Windows ACLs. POSIX file-mode hints alone are not a Windows ACL guarantee.

## Triggers and evidence

Managed sessions automatically capture loading milestones, failed loading/navigation, missing name selectors and failed/successful reviewed view checks. The restricted MCP gateway adds `sfqa_browser_debug_capture` with **no arguments**, for an operator-requested capture during the same authorized session; native MCP screenshot/evaluate/file/URL tools are still not exposed. Its result contains sanitized metadata and a local filename, never image bytes. Failed reviewed steps capture local evidence without changing their one-use failure/replay status.

Generated tests using a visual-enabled reviewed guard capture and attach evidence in `afterEach`. The unchanged assertion determines the test outcome. The real supported `TestInfo.attach` API supplies PNG attachments to Playwright and local reportingLabs. Automatic unmasked runner screenshots are disabled for `live-salesforce` generated execution, and its traces remain disabled by the dedicated pipeline. Legacy fixture behavior remains. Failures at/after expiry may have only the earlier bounded milestone images; no post-expiry capture is attempted.

Each context writes:

```text
artifacts/browser-debug/<run-id>/<session-uuid>-01.png
artifacts/browser-debug/<run-id>/<session-uuid>.json
artifacts/browser-debug/<run-id>/index.html       # generated by preview command
```

The manifest binds policy/session/run/validation, image SHA-256 and byte count, reason, elapsed time, readiness/loading/error categories and finite blocked-request counts. A name visible in a screenshot is not independent content proof. `LightningSession.close()` links the manifest to its report and retains independent pre/post record checks. A visual-enabled live readiness receipt also needs a successful reviewed-view screenshot manifest; images alone cannot mint readiness, mutation approval or learning.

Primary APIs: [Playwright screenshots](https://playwright.dev/docs/screenshots), [screenshot masking/options](https://playwright.dev/docs/api/class-page#page-screenshot), [TestInfo attachments](https://playwright.dev/docs/api/class-testinfo#test-info-attach), and [reportingLabs attachments](https://reportinglabs.dev/features/report-tour/). The installed reporter is exercised locally rather than assuming an undocumented attachment API.

## Commands

Generate safe, synthetic retained examples (no Salesforce/model/state use):

```powershell
npm.cmd run platform -- demo-browser-debug SFQA-VISUAL-OFFLINE-LOCAL-001
npm.cmd run platform -- browser-debug-preview SFQA-VISUAL-OFFLINE-LOCAL-001
Invoke-Item -LiteralPath .\artifacts\browser-debug\SFQA-VISUAL-OFFLINE-LOCAL-001\index.html
```

The preview command verifies manifest scope, contained paths and image hashes before generating a static, script-free local HTML page. It opens no browser automatically. The operator's image/HTML viewer is separate from headless framework execution. No HTTP server, arbitrary file opener or shell command is exposed to MCP.

For **freshly approved** observation policies only:

```powershell
npm.cmd run platform -- lightning-review .state/VISUAL_REVIEW_INPUT.json
# Review/activate the exact new policy AND its separate native risk receipt.
npm.cmd run platform -- lightning-observe .state/APPROVED_VISUAL_POLICY.json .auth/APPROVED_STATE.json --via compare
npm.cmd run platform -- browser-debug-preview APPROVED_RUN_ID
```

`--via compare` navigates once through direct Playwright, observes with direct Playwright and the real private MCP connection in the **same context**, and does not replay a one-call initialization grant. It is not a normal/unrestricted reference. If no selector contract was reviewed, finite observations and images remain discovery proposals and no rendering receipt is issued. `lightning-session-latest.json` and `lightning-session-final.json` stay under `.state`; failures before session creation produce only the finite gate diagnostic and no record-page image.
