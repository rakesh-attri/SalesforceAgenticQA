# Live Salesforce goal-directed observation

This adapter extends the existing exploration planner, SQLite ledger, LangGraph
selection graph, LightningSession and restricted Playwright MCP gateway. It does
not authorize a live lifecycle. Package 012 remains declined and inactive.

The dependency chain is current specification/application study and saved
journal-backed page evidence → reviewed observation references → separate exact
browser/profile/API-read approval → fresh API/native identity → planner choice
and durable intent → isolated headless Chrome/MCP observation → independent
equality/drift checks → source-linked local report and proposed investigation.

## Source domains and explicit compatibility

Browser sourceVersion may be a specification hash, not metadataVersion. The saved
9c734a03… / f4011604… mismatch was explained using original producers and identical
metadata, not bypassed. [Source reconciliation](SOURCE_EVIDENCE_RECONCILIATION.md)
describes the separate typed lineage, host-journal evidence and named review. A
preparation observation can carry its matching lineage review path; both original
hashes remain unchanged. Unknown/incompatible cases still reject. Historical
readiness remains expired evidence and does not authorize the new observation.

## Implemented boundary

`SALESFORCE_OBSERVATION` supports one exact existing Account and optionally one
exact existing Contact. Each object has its own single-use browser grant, native
profile, reviewed view and closed API-read grant. A selected `observe-record`
reference navigates to that record, observes the original name, independent
content/tabs, busy/error checks and stability, and collects bounded name-locator
proposals through the existing private same-context Playwright MCP transport.

Agents receive object/reference identifiers and sanitized receipts. They receive
no Page/context, raw snapshot, arbitrary URL/SOQL, storage state, native MCP tool,
JavaScript evaluation or record values. No additional public MCP tool is added.
Tabs/related-list structures are observable only where already present in the
reviewed view. Arbitrary field locators, tab clicks, relationship-link clicks,
list expansion and layout-specific visibility need their own supported contract.
The native profile still limits interactions to the separate owned-action broker.

Account reads are limited to Id, Name and LastModifiedDate. Contact may additionally
read LastName and AccountId. Queries are constructed internally with an exact ID
and LIMIT 1. Raw values remain in the trusted host; receipts retain hashes,
reviewed field names and equality classifications. Contact.AccountId is compared
only with the separately approved Account; foreign records are never followed.
Missing/null/denied data stays unknown. UI/API presence is not proof of FLS,
effective permissions or sharing. Name comparison uses the API-bound original
Lightning view; additional value/visual/business oracles remain partial.

Direct navigation between independently observed records is labeled
`direct-record-navigation`, with `relationshipTraversal:false` and
`businessTransactionObserved:false`. Metadata relationships remain inferred until
an independently checked relationship receipt exists. Existing immutable study,
journey review and verified-learning mechanisms remain the publication boundary;
these observations do not silently replace reviewed models or create lessons.

## Approval, durability and effects

All leaf browser/profile/read approvals and the exploration definition must be
exact, current, named and scoped to the same dedicated org, user/persona,
application, build, engine, origins, state binding and metadata version. The
aggregate grant cannot outlive any leaf grant. Normal Production and sandbox
modes cannot inherit these permissions. Preparation always writes REVIEW_REQUIRED
and never activates a profile, changes the preference, renews parent factory
approval, resets quotas or replaces a run.

Normal networking requires the existing separate acceptance of unreviewed and
potentially irreversible native background effects and reviewed dedicated-user
access. It is not proof of read-only server purity. Native request/byte limits
close after observation; they do not prevent in-flight effects. Browser safety
planes and existing Production policies are unchanged.

The common ledger journals intent before opening Chrome. Each native context
pre-reserves its entire reviewed request allowance; receipts show actual counts.
This conservative reservation is never refunded. Sessions/time/navigation/actions
are cumulative, and abandonment is charged. A pending, failed/incomplete or
uncertain native attempt cannot replay. Only the remaining unattempted reference
can continue after an exact original LangGraph interrupt and fresh identity,
source and independent-record baseline checks. Drift revokes prior coverage.
Expired/consumed grants cannot renew through resume or report commands.

Failure investigation reuses the existing hypotheses, source/history retrieval,
duplicate suggestions and minimum follow-up recommendations. Console/transport,
readiness, API equality and local masked images remain evidence, not confirmed
causes. Locator-only proposals preserve the original assertion and require both
current observed and source-supported candidates. They grant no replay or repair
execution; uncertain native effects require separate operator review. No
exploration observation is recorded as a generated Playwright test pass.
reportingLabs remains reserved for actual generated test execution.

## PowerShell commands

Run the deterministic local demonstration (actual installed headless Chrome and
Playwright MCP, synthetic Salesforce API/browser responses, zero Salesforce calls):

```powershell
npm.cmd run platform -- demo-live-exploration
```

Create a private `.state/observation-input.json` with existing `history` and
`browserHistory` SQLite paths, `parent`, `org`, `graph`, approved `.auth` `statePath`,
a new `runId`, named `operator`, and `observations` containing saved
`review`/`report`/`view` paths. All JSON/database inputs must be contained under
`.state`. Preparation reads only local sources and the approved state binding:

```powershell
npm.cmd run platform -- live-exploration-prepare .state/observation-input.json
Get-Content .state/live-exploration-<run-id>/manifest.review.json
```

If a source mismatch lacks an exact compatible lineage link, preparation produces
only a **blocked-source-drift** manifest. Reconcile artifact domains before inferring metadata drift. It creates no executable definition or
session grant. Reconcile/review the source evidence first; changing a hash is not
source verification. Otherwise inspect definition, original assertions, every
leaf browser/profile/read hash, original expiry and separate native-risk receipt.
The operator must explicitly authorize the exact package; agents must never fill
approval names or activate permissions on their own.

The manifest includes the inactive draft hash and exact proposed post-approval
hash. Only after explicit authorization may a separate named authorization JSON
(original definitionHash, nonce and expiry) be supplied through the run input's
authorization path and applied using live-exploration-activate. The command checks
the unchanged export, changes named approval fields only, writes once and executes
no browser. Use its returned run.approved.json for execution. Full commands and
the separate native risk disclosure are in the source reconciliation guide.

Only after that separate authorization and independent fresh state verification:

```powershell
npm.cmd run platform -- live-exploration-run .state/live-exploration-<run-id>/run.json
npm.cmd run platform -- live-exploration-report .state/live-exploration-<run-id>/run.json
Start-Process '<returned-local-index.html>'
```

For an interrupt, add `resume` pointing to a private JSON containing original
`operator`, `definitionHash`, `actionId`, `stateHash`, and `decision` (`continue` or
`stop`) in the run configuration, then invoke `live-exploration-resume`. It cannot
replace a definition/approval or restore a consumed native context. Add exact
`criterionId` for `live-exploration-investigate`. Report commands have no network
authority; images require exact manifest/session/policy/run/validation and file
integrity and stay local. Masking is best effort, with no AI/upload use.
